§10 — The five questions, answered

Annotation UI — Electron, Tauri, or web + local server?ADC-005

The framing dissolved under the evidence. ProRes decodes in no webview and has no WebCodecs codec string, so proxy transcode is unconditional — and since transcoding is mandatory anyway, composing both camera angles into one side-by-side all-intra H.264 file per clip makes multi-angle sync perfect by construction and scrub latency single-stream. Once sync is solved in the pipeline, the framework barely matters.

Decision: build, don't adopt (no surveyed tool combines two-angle sync, waveform, rich schema forms, and 2-min/clip keyboard cadence — the schema form is the product). Vanilla JS + FastAPI bound to 127.0.0.1 with a token; Tauri held as a packaging escalation. Cheap hedges first: a half-day ELAN trial and a week-1 browser scrub prototype.

Storage — GCS + local NVMe, or fully local given PHI?ADC-006

Both. The assumed blocker doesn't exist: Google's HIPAA BAA is self-serve, electronic, and has no minimum spend — a solo practice can execute it in minutes. Local encrypted NAS is the working tier where selective retention culls the 100–200 GB/hr firehose; GCS Coldline→Archive (≈$1.2–4.4/TB/mo) with CMEK is the immutable offsite leg — replacing manual drive rotation, the leg most likely to fail under solo operation. Use per-object legal holds, not locked bucket retention: irrevocable WORM would prevent honoring a consent revocation, and CMEK gives crypto-shred. HHS is explicit that client-side encryption does not remove the BAA requirement.

Which prosody / affect models run on 64 GB Apple silicon?ADC-008

All of them — audio derive runs sub-realtime (~6–14 min per 15-min encounter; ~15–35 min with the video cascade). mlx-whisper large-v3-turbo (2× whisper.cpp on M-series); word timing from CTC forced alignment, not Whisper's drifting DTW timestamps; pYIN + RMS + pause/rate for prosody, deliberately avoiding openSMILE (research-only license) and Praat (GPL). Skip pyannote entirely — per-speaker lapel tracks make channel = speaker. On affect: arousal from audio is trustworthy, valence is not, so emotion models are a ranking signal for the review queue, never a classifier. MediaPipe landmarks run continuously; py-feat AUs only inside audio-flagged windows.

Manifest format that survives five years — WebDataset, Arrow, or custom?ADC-007

The boring one, deliberately: content-addressed native media files (BLAKE3 names), an append-only JSONL manifest as ground truth, SQLite for annotations, JSON provenance sidecars, and BagIt-style batch checksums. At thousands of clips, columnar formats buy nothing measurable — and their stability records argue against them (Lance: three format iterations in ~2 years; HF datasets v4.0 broke its own caches). JSON and SQLite have perfect records. Training-stack formats are emitted on demand and treated as disposable — the plan's own design rule, now evidence-backed.

Can Tier 3 (coaching) ship first on a small corpus?

Yes. Lyssn.io — the closest comp — built a real business on models trained from roughly 341–1,553 expert-coded sessions; the projected 500–2,500 clips is the historically demonstrated scale, and modern base models lower the bar (at ~500 clips, retrieval + many-shot in-context conditioning works with no training run). Zero-shot LLMs measurably underperform on fine-grained communication coding — the expert corpus is the moat. Regulatory: clinician-facing retrospective education tools are on FDA's explicit non-device list. No Lyssn-for-medical-encounters exists; that lane is open. Standing risk: ambient-scribe vendors own the audio pipe and could enter fast.

ADC-004 — Implementation language

Hybrid: Rust core, Python derive — user-decided, evidence-aligned

Rust owns the never-lose-data path — ingest, capture-validation, fixity verification, one static binary (harness ingest / harness validate). Its one decisive, evidence-backed advantage is 5-year bit-rot immunity: a documented 6-year-old Rust project revived in minutes, while a 2026 ML venv likely won't survive to 2031. Python keeps everything research-shaped — derive, candidate detection, UI backend — because the ML tooling lives there and full Rust would tax every model swap with an ONNX-export-and-port project. Coupling is a filesystem contract only: Python never writes into the raw store; Rust never imports a model.

Negative finding worth keeping: the supply-chain security argument for Rust is mostly a myth. crates.io does no automated malware scanning at upload, and build.rs executes arbitrary code at build time exactly like setup.py. The durable PHI controls are FileVault, an egress-filtered capture machine, and hash-locked installs in both ecosystems — not the language.

Correction to §8.7: the plan names annotation labor the most likely cause of death. Under the plan's own §4.1 assumption (performance moments are a handful per shift), it isn't — supply is. Even the aggressive scenario needs under one hour per week of annotation.

Consequences: the consent instrument (§0.5) is corpus-size-determining, not a compliance formality; annotation-UI speed is deprioritized in favor of correctness and low friction; the moderate scenario clears the LIMA-style ~1k threshold, which the Tier-3 research says is enough to build on. Rerun scripts/throughput_model.py with real shift numbers after the first recorded month.
